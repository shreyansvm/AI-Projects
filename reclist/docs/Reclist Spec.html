Reclist Product Spec

Product

Reclist is a personal wishlist for recommendations from people you trust — movies, restaurants, parks, museums, anything — all in one place, with who told you.

Problem

When family and friends recommend a movie, restaurant, or place of interest, the recommendation lives in a text thread or in memory — and quietly disappears. By the time you're free on a Friday night or planning a weekend, you can't recall who said what, or whether you've already tried it.

Existing tools solve part of this: Letterboxd covers movies, Google Maps saves cover places, Notes catches everything else — but they're siloed, they lose the "who told you" context, and none give you a single view across all categories.

Core insight

88–93% of consumers trust recommendations from friends and family more than any other source. Yet there is no default system for preserving them.

User

Primary persona

Shreyans — parent in his 30s, socially active in a close family and friend circle. Asks people he trusts for recommendations constantly but has no system for capturing them. Has young kids, so every movie night or weekend outing decision carries weight — time is scarce, bad picks are costly.

Current workarounds

Starred texts, screenshot folders, Notes app lists with no context, siloed saves in Letterboxd / Google Maps / Yelp. All lose the "who told me and why."

What he actually wants

One page. Everything across every category. Who recommended it. Add it in under 10 seconds while the conversation is still fresh.

User Stories

US-01As Shreyans, I want to add a recommendation in under 10 seconds so I can capture it before I forget the context.
US-02As Shreyans, I want to see all my recs on one page grouped by category so I can browse everything at a glance.
US-03As Shreyans, I want every card to show who recommended it so the social context is never lost.
US-04As Shreyans, I want to filter by category so I can find "what movie should we watch tonight" quickly.
US-05As Shreyans, I want to mark an item done so my wishlist stays focused on what's still ahead.
US-06As Shreyans, I want to undo a "done" mark in case I tapped it by accident.
US-07As Shreyans, I want to add a note to a rec (what they said about it) so the reason behind the recommendation isn't lost.
US-08As Shreyans, I want to send a rec or my full list to a friend's Gmail so recommendations travel back out as easily as they came in.
US-09As Shreyans, I want to switch between a compact Board view and an editorial Shelf view depending on my mood.

Design

Reclist has two modes — Board and Shelf — sharing a common component language but each with its own mood. Board is modern and spatial; Shelf is editorial and calm.

Visual Direction

Board

Light neutral background, white cards on a grid, colored accent bars per category. Dense, scannable, card-first. Feels like a personal Notion or Airtable.

Shelf

Warmer parchment background, fixed sidebar nav, Instrument Serif for headings. Numbered list with Serif titles. Feels like a reading list or a favourite notebook.

Accessibility Notes

All interactive elements use cursor: pointer. Focus styles should be added for keyboard navigation (currently implicit via browser defaults — add explicit :focus-visible outlines before shipping). Color is never the only differentiator — category labels accompany accent colors on every card. Animation respects prefers-reduced-motion — add @media (prefers-reduced-motion) guards before v1.

Key Design-to-Code Notes

The .dc.html format

The design file uses a custom reactive component format (<x-dc>, <sc-if>, <sc-for>) backed by support.js. The entire component logic lives in a DCLogic class with a renderVals() method that returns flat key-value pairs consumed by the template. This maps 1:1 to a React component with useState + derived values — no significant architectural lift.

Styles

All styles in the design file are inline strings using oklch() color. Port these to Tailwind utility classes + a tailwind.config that defines the four category accent colors as custom tokens. Keep oklch — it's supported in all modern browsers and is already the design's color model.

Animation

Two keyframe animations — rl-rise and rl-slide — defined in the design file's <helmet> block. Add these to globals.css and reference via Tailwind's animate-* or animation utility.

Grid columns

Board grid uses minmax(232px, 1fr) in "All" view, switching to minmax(400px, 1fr) for single-category views. This gives wider cards when there's more horizontal space — keep as a dynamic inline style or Tailwind JIT arbitrary value.

Con

More manual setup vs Clerk's hosted UI; no magic links / SMS without extra work
